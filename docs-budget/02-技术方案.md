## 一、核心架构决策

### 1.1 决定性发现：**不要给写入点加钩子**

全仓库有 **14+ 处**创建 `TxRecord` 的位置：

```
src/app/api/v1/record/ingest/route.ts:718, 779, 1164
src/app/api/v1/statement/import/route.ts:1367, 1439, 1731
src/app/api/v1/business-transactions/link-cash-flow/route.ts:138, 221, 292, 367, 505
src/app/api/v1/fx-conversions/route.ts:221, 237
src/app/api/v1/init/route.ts:104
... 还有 createMany 的批处理路径
```

**若给每处加「记账后检查预算」，等于把预算逻辑散布到整个代码库** ——
任何一处漏改就是静默失效，且严重阻碍日后合并上游更新。

> **决策：预算走旁路（out-of-band），不侵入写入路径。**

### 1.2 旁路方案：复用已有的系统定时任务

MMH **已有**完整的系统任务框架：

```
src/lib/server/system-tasks.ts            runDueSystemTasks()      ← 挂载点
src/instrumentation-node.ts               调度器（默认每 10 分钟）
src/lib/server/scheduled-task-lock.ts     并发锁
```

`system-tasks.ts` 的现有模式正是我们要的（遍历所有 household 做周期性维护）：

```ts
// 现有代码（src/lib/server/system-tasks.ts:15-20）
export async function runDueSystemTasks() {
  const households = await prisma.household.findMany({ select: { id: true } });
  for (const household of households) {
    try {
      // ... 现有任务：materializeDueInstallmentPayments / ensureAccountGroupMemberPairing
    } catch (error) {
      logger.error("... failed for household", "system-task", { householdId: household.id, error });
    }
  }
}
```

**调度参数**（`src/instrumentation-node.ts:9-12`）：
- 默认间隔 **10 分钟**（`MMH_SYSTEM_TASK_INTERVAL_MS`）
- 启动时也跑一次
- `MMH_SYSTEM_TASKS_DISABLED=1` 可关闭

**我们的做法**：在 `runDueSystemTasks()` 里增加一段预算扫描，
与现有任务**并列且隔离**（各自 try/catch，一个失败不影响另一个）。

### 1.3 三个层次的职责划分

```
┌─ 展示层（页面）────────────────────────────────┐
│  预算进度 = 实时聚合查询（不落库）              │
│  打开页面就能看到最新进度，无需等定时任务       │
└───────────────────────────────────────────────┘
┌─ 警告层（系统任务，每 10 分钟）───────────────┐
│  扫所有 household 的启用预算                    │
│  跨过阈值 → 写 BudgetAlert（唯一约束天然去重）  │
│  可选：发邮件                                   │
└───────────────────────────────────────────────┘
┌─ 数据层（Prisma）─────────────────────────────┐
│  Budget / BudgetAlert 两个新模型                │
└───────────────────────────────────────────────┘
```

**关键点**：进度是**算出来的**不是存出来的 → 天然不会与流水不一致。

## 二、数据模型

### 2.1 新增两个模型（写进 `prisma/schema.prisma`）

需遵循 MMH 现有约定（`cuid()` 主键、`householdId` 多租户、`@@index`）：

```prisma
/// 月度预算（类目级或总预算）
model Budget {
  id          String   @id @default(cuid())
  householdId String
  categoryId  String?                    // null = 总预算
  amount      Decimal  @db.Decimal(18, 2)
  period      String   @default("monthly")
  alertPct    Int      @default(80)
  enabled     Boolean  @default(true)
  note        String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  Household   Household @relation(fields: [householdId], references: [id], onDelete: Cascade)
  Category    Category? @relation(fields: [categoryId], references: [id], onDelete: Cascade)

  @@unique([householdId, categoryId])
  @@index([householdId, enabled])
}

/// 预算警告记录（(budgetId, periodKey, level) 唯一 → 天然幂等去重）
model BudgetAlert {
  id         String    @id @default(cuid())
  budgetId   String
  periodKey  String                      // "2026-10"
  level      Int                         // 80 / 100
  spent      Decimal   @db.Decimal(18, 2)
  amount     Decimal   @db.Decimal(18, 2)
  notifiedAt DateTime  @default(now())
  readAt     DateTime?

  Budget     Budget @relation(fields: [budgetId], references: [id], onDelete: Cascade)

  @@unique([budgetId, periodKey, level])
  @@index([periodKey])
}
```

**还需在 `Household` 与 `Category` 模型上加反向关系字段**（Prisma 要求两边都声明）。

### 2.2 SQLite 兼容性 —— 已自动解决

`scripts/generate-native-sqlite-schema.cjs` 会从 `schema.prisma` **自动生成**
`schema.native.prisma`：

```js
// 逻辑：datasource 换成 sqlite + 去掉所有 @db.* 装饰器
.replace(/datasource\s+db\s+\{[\s\S]*?\}/, `datasource db { provider = "sqlite" }`)
.replace(/\s+@db\.[A-Za-z]+(?:\([^)]*\))?/g, "")
```

→ 我只需改 `schema.prisma`，然后**跑一次生成脚本**即可，不用手工维护两套。

### 2.3 迁移

`prisma/migrations/` 现有 106 个迁移，命名形如 `20260905_add_account_loan_type`。
新增一个 `20261011_add_budget`。

> ⚠️ 项目有 `npm run check:migration-coverage`，要确保新模型被迁移覆盖。

## 三、可复用的现有资产（**不重复造轮子**）

### 3.0 必须遵守的代码约定（照抄现有风格）

**API 路由**（模板 `src/app/api/v1/settings/catalog/route.ts`）：

```ts
import { NextResponse } from "next/server";

/**
 * GET /api/v1/budgets
 *
 * Success: { ok: true, data: ... }
 * Failure: { ok: false, code: string, error: string }
 */
export async function GET(req: Request) {
  // 鉴权：读用 getApiHouseholdScope(req)（支持 API key）
  //       写用 getHouseholdScope()（要求登录会话）
  return NextResponse.json({ ok: true, data });
}
```

约定要点：
- 响应**永远是** `{ ok: true, data }` 或 `{ ok: false, code, error }`
- 错误用**大写下划线**错误码（如 `INVALID_SURFACE`）+ `{ status: 400 }`
- 每个 route 顶部写**用法的 JSDoc**
- 几乎所有路由都声明 `export const runtime = "nodejs"`

**页面**（`src/app/(sidebar)/*/page.tsx`）多为 **Server Component**
（直接 `import { prisma }`），交互部分拆成 `src/components/` 下的 Client Component。
例如 `statistics/page.tsx` 506 行，是 Server Component，图表拆到
`src/components/StatisticsCharts.tsx`。

if (connectionString === ":memory:" || connectionString.startsWith("file:")) {
