## 一、已锁定的决策（2026-10-11 用户确认）

| 编号 | 决策点 | **结论** |
|---|---|---|
| **D1** | 预算粒度 | **类目预算 + 总预算**（不做账户维度、不做收入目标）|
| **D2** | 豁免类目默认集合 | **贷款本金 · 房贷 · 房租 · 信用借还 · 信用卡还款** |
| **D3** | 提醒方式 | **页面横幅**（零依赖，最可靠）|
| **D4** | 阈值分级 | **两级：80% 预警 / 100% 超支**（学 MX）|
| **D5** | 每日可用额度 | **P2 再做**（MVP 不含）|

### 决策带来的设计含义

**D1 = 类目 + 总预算** → `Budget.categoryId` 可为 null 表示总预算，
用 `@@unique([householdId, categoryId])` 保证每类目一条、总预算一条。

**D2 = 五个豁免类目** → 这五个类目**不计入总预算**。
注意用户账本里这五类合计 **¥599,418，占支出 69%**：
```
贷款本金 ¥310,653 · 信用借还 ¥128,842 · 房贷 ¥97,525
信用卡还款 ¥23,906 · 房租 ¥38,492
```
→ 总预算实际管的是**剩下 31% 的日常消费**（餐饮、日用、教育、医疗、交通等）。
这个数字必须让用户看到，否则会误以为"总预算 ¥X"能管住全部支出。

**D3 = 页面横幅** → 不引入邮件依赖，不改 `src/lib/mail/`。

**D4 = 两级阈值** → `level` 取值只有 `80` 和 `100` 两个，
`@@unique([budgetId, periodKey, level])` 天然去重。

**D5** → MVP 不实现，但数据模型预留（未来加 `dailyPace` 之类字段不用改表结构）。

## 二、数据模型（最终版）

写进 `prisma/schema.prisma`：

```prisma
/// 月度预算：categoryId 为 null 表示「总预算」（不含豁免类目）
model Budget {
  id          String   @id @default(cuid())
  householdId String
  categoryId  String?
  amount      Decimal  @db.Decimal(18, 2)
  period      String   @default("monthly")
  alertPct    Int      @default(80)
  enabled     Boolean  @default(true)
  note        String?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  Household   Household @relation(fields: [householdId], references: [id], onDelete: Cascade)
  Category    Category? @relation(fields: [categoryId], references: [id], onDelete: Cascade)
  BudgetAlert BudgetAlert[]

  @@unique([householdId, categoryId])
  @@index([householdId, enabled])
}

/// 预算警告记录：(budgetId, periodKey, level) 唯一 → 天然幂等去重
model BudgetAlert {
  id         String    @id @default(cuid())
  budgetId   String
  periodKey  String                      // "2026-10"
  level      Int                         // 80 | 100
  spent      Decimal   @db.Decimal(18, 2)
  amount     Decimal   @db.Decimal(18, 2)
  notifiedAt DateTime  @default(now())
  readAt     DateTime?

  Budget     Budget @relation(fields: [budgetId], references: [id], onDelete: Cascade)

  @@unique([budgetId, periodKey, level])
  @@index([periodKey])
  @@index([readAt])
}
```

### 必须同步修改的既有模型（Prisma 要求双向声明）

| 模型 | 加什么 | 位置 |
|---|---|---|
| `Household` | `Budget Budget[]` | `Household` 关系列表末尾 |
| `Category` | `Budget Budget[]` | 紧跟 `transactions TxRecord[]` 之后 |

### 豁免类目怎么存

**不建新表**，用**类目名常量**在代码里判定（见 `src/lib/budget/period.ts`）：

```ts
export const BUDGET_EXEMPT_CATEGORY_NAMES = [
  "贷款本金", "房贷", "房租", "信用借还", "信用卡还款",
] as const;
```

**理由**：豁免集合是**业务约定**且需要用户可改；
用代码常量 + 未来可升级为 `SystemSetting` 里存覆盖值，
避免 MVP 阶段为此再建一张表。

> ⚠️ 注意：用户账本里的实际类目名必须**逐字匹配**。已核对：
> 从 `/api/v1/statistics` 实测，这五个名字都真实存在。

## 三、聚合口径（最关键，决定用户信不信）

**预算的「已花」必须与 `/statistics` 页面同口径**，否则两个页面数字打架。

### 3.1 取数规则

```ts
// 伪代码
本月该类目已花 =
  SUM(ABS(amount))
  WHERE householdId = ?
    AND type = 'expense'                 // 只算支出
    AND deletedAt IS NULL                // 排除软删
    AND date >= 月初 AND date < 下月初    // 不含下月首日
    AND categoryId = ?                   // 类目预算：指定类目
    AND NOT isCreditCardRepaymentTransfer(...)   // 排除内部流转
    AND NOT isLiabilityPrincipalSource(...)      // 排除负债本金
```

**总预算**额外排除五个豁免类目。

### 3.2 已实测确认的技术细节

**`TransactionType` 枚举**（`prisma/schema.prisma`）：

```prisma
enum TransactionType {
  expense     // 支出 → 预算统计只算这个
  income      // 收入
  transfer    // 转账
  investment  // 投资（如股票买入）
}
```

用户账本里的实际分布（2026-10-11 实测）：
```
expense 1230 · income 116 · investment 3
```
→ **只有 `expense` 计入预算**，其余三种一律排除。
注意 `investment` 只有 3 笔（股票买入），但也要排除，否则买股票会被算成消费。

**⚠️ 未分类占比 22.1%，是总预算的最大盲区**（实测）：

```
无 categoryId 的支出：410 笔  ¥191,988.91
占全部支出（¥868,162）的 22.1%
```

**处理方式**：
- 「未分类」作为**一个显式桶**出现在预算页，让用户看得见
- 在**总预算里计入**（否则会系统性低估实际花费）
- UI 上对这个桶加提示，引导用户去分类

**待实现时确认的细节**：
- **月初/月末的时区**：生产环境 `TZ=Asia/Shanghai`。
  必须用与 `/statistics` **完全相同**的边界算法，否则月初/月末差一天。
  实现时**直接复用现有函数**，不自己算。
